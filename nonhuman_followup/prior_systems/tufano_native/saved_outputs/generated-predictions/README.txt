For each model (1-encoder, 2-encoder) and for each beam size (k) we provide both the abstracted predictions (i.e., the ones actually generated by the models) as well as the corresponding raw source code that, as explained in our paper, can be automatically reconstructed from the abstracted code.

In each file (both the ones reporting the abstracted and the raw code) we report for each entity in the test set 1) INPUT_NL (i.e., the pre-processed reviewer comment, only available for the 2-encoder model); 2) INPUT_CODE (i.e., the code submitted for review, m_s); 3) the ORACLE (i.e., the correct output, m_r), and 4) the k PREDICTIONS generated by the model.

To increase the readability of the files we:
1. Put the cases in which a perfect prediction has been generated on top (this means that the order of the predictions might be different in the files related, e.g., to the 1-encoder and to the 2-encoder).
2. In the files showing the raw source code, we flattened each entry (i.e., the oracle and each prediction) on a single line by replacing new lines with a space.
